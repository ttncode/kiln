# kiln — the design, read back from the user's seat

> **What this file is.** `2026-09-19-kiln-architecture.md` describes kiln from the builder's
> chair: decisions, rationale, mechanisms. This file is the same system described from the
> **user's chair** — what a stranger installs, types, sees, and is told when it breaks. It is
> derived from the architecture file and adds no decisions of its own.
>
> **Why it exists.** Reading the design this way is an instrument, not a courtesy. The fifth
> review pass (audit companion §7) came from doing exactly this and found two blockers that
> four builder-seat passes had walked past — because a builder reads a section to check it is
> consistent, and a user reads it to check it *does the thing*. Keep this file current and run
> the read-back again before P1 and before v1.0.
>
> **Authority.** The architecture file wins every disagreement. If this file and it diverge,
> this file is stale — fix it here, never there.
> Derived from D1–D106. Last updated: 2026-09-23 — the read-back this file's own header
> asks for before v1.0. What it found is in `2026-09-23-pre-v1-audit.md`.

## 1. The first ten minutes

```
/plugin marketplace add <you>/kiln:kiln
/plugin install kiln
/kiln:kiln init
```

`init` detects the stack from disk (`package.json` / `tsconfig` / `composer.json` / `pom.xml`),
detects the git remote, and asks a clone **three questions, each with a default**: which
branches must never be pushed to, what runs the tests, and what runs a fast subset of them.
Two more appear only where kiln refuses to guess — one if nothing names a default branch, one
if no remote names a forge. `node scripts/decision-count.mjs` prints the number (B06).

| What the user never has to do |
|---|
| a token · Docker · Python · CI · install a second plugin |

Any of those appearing in `init` is a regression, not a requirement (D6, D2, D62).

| Situation | Behaviour | Decision |
|---|---|---|
| `.kiln/` already exists | **additive**: reports what exists, writes only what is missing, overwrites nothing, points at `kiln doctor --write` | D60.4 |
| no git repo, or no commit yet | `init` still works; the run refuses at the first stage needing a base, naming it | D60.5 |
| `config.json` has a UTF-8 BOM, or CRLF | reads fine — BOM stripped before `JSON.parse`, line endings never rewritten | D60.6 |

**Concepts a stranger must learn in their first ten minutes: two** — the `.kiln/` directory, and
the three ceremony paths. Project rules are a third concept and deliberately not one of them:
`init` writes an empty router, and a project that never fills it in never meets the idea.

## 2. Starting a piece of work

| Typed | Meaning |
|---|---|
| `/kiln:kiln "the export button on the reports page does nothing"` | a sentence — **the primary entry point** |
| `/kiln:kiln https://github.com/you/app/issues/42` | a URL |
| `/kiln:kiln 42` | a tracker ref, or a work id in progress |
| `/kiln:kiln` | lists work in progress |

A **tracker is never required**. A ticket URL is one way to obtain the text of the work, not the
way in (D13, §3b).

| Input | `<id>` becomes | Decision |
|---|---|---|
| `PROJ-123` or `42` | verbatim, as the tracker writes it | D51 |
| a sentence | `<yyyymmdd>-<4–6 word slug>` | D51 |
| multi-repo with more than one ticket-owning module | the owning module as a prefix | D51 |

`init` · `doctor` · `dna` are **reserved words**, resolved before every branch of the argument
order; a work id may not take one, or `work/dna/` would shadow the command (D79.4). A directory
that exists but is not resumable for this argument makes kiln print both and **refuse** — it
never reuses another work's directory (D51).

## 3. What a `bounded` run looks like

```
investigate → classify (out loud, overridable)
            → short design → rules → GATE
            → code + fast steps → self-review → rules → GATE
            → verify → ship
```

`rules` is `kiln rules <id>`: the project's own rules, matched by path glob against the files
that stage names, printed in full. At PLAN it meets the change preview, so a rule shapes the
plan; at REVIEW it meets the diff that actually happened, so a rule still reaches a file the
plan never predicted. What was handed over is recorded in `state.rules[]` (D101).

Right after classification the orchestrator emits a **todo list**, and **gates are their own
items** — so the list shows at a glance whether kiln is working or waiting on a human (D25).

| Path | When | Gates | Artifacts | Can ship? |
|---|---|:--:|---|---|
| `spike` | a question, not yet clear enough to build | 1 | `findings.md` | **no** |
| `bounded` | clear, moderate | 2 | brief · plan · review | yes |
| `full` | large | 4 | + spec | yes |

One-way ratchet: up, never down. The user overrides by saying `"full"` (D12).

## 4. The four gates of `full`

| # | Key | After stage | What the user reads | What they are approving | What it unlocks |
|---|---|---|---|---|---|
| 1 | `spec` | SPEC | `spec.md` | the problem, acceptance criteria, **Out of scope** | only the move to PLAN |
| 2 | `plan` | PLAN | `plan.md` + **change preview** | how, which files, **Review Focus** | **source edits** + writes `predicted[]` |
| 3 | `review` | REVIEW | `review.md` + the `Scope —` line | accepting the review's result | only the move to VERIFY |
| 4 | `ship` | after VERIFY | the PR body | opening the PR | **the SHIP commit and the PR** |

`bounded` has gates 2 and 3 only, and its *accept* at gate 3 **is** accept-and-ship. `spike` has
`probe` alone (§3e, D49).

Every gate stores `{decision, artifact_sha, answer, by}`:

- `artifact_sha` binds approval to the document the user actually read. **Editing `plan.md` after
  approval blocks the next source write** (D65).
- `answer` is the user's words **verbatim**, reprinted in the final report and the PR body — so a
  fabricated approval is a visible lie in their own words, not a silent flip (D65).

Not a yes, each re-asked rather than accepted (D21b): *"whatever you think"* (→ re-asked as two
concrete options) · *"sounds good"* · *"sure let's go"* · silence.

**Gate 4 is enforced, not prompted** (D77):

```
SHIP_AUTHORIZING = { spike: null, bounded: "review", full: "ship" }
```

`null` means no gate can satisfy it, so `spike` can never open a PR. `pre-bash` matches
`gh pr create` / `glab mr create` and blocks until the path's key is approved.

## 5. Why `spike` cannot ship, and what happens to its code

| What SHIP needs | `bounded`/`full` | `spike` |
|---|---|---|
| an approved `plan.md` | yes | no PLAN stage |
| `predicted[]` + change preview | yes | no plan gate |
| the reconciliation line | yes | no REVIEW |
| `review.md` | yes | none |
| `state.verify[]` | yes | no VERIFY |

Shipping a spike means opening a PR **nothing reviewed and nothing verified**.

Ratcheting up to `bounded`: SHIP is kiln's only commit point (D36), so a spike's source is
**uncommitted working-tree changes**, and kiln does neither of the two obvious things (D78):

| kiln does not | Because |
|---|---|
| delete it | that is D7 item 2 — *destroys data unasked* — performed by kiln itself |
| carry it forward silently | it was authorized by `probe`, not `plan`; carrying it launders pre-plan code into a shipped change past D65 |

Instead: a **halt with the numbered menu** every other irreversible choice already uses. It prints
the spike's `git diff --stat`, states that anything kept will surface at REVIEW as *beyond
prediction* — the reconciliation doing its job, not a new warning — and leaves the tree untouched
either way. The ratchet is recorded as `carry_over[] = {from_pass, kind: "ratchet", text}`.

## 6. Three failure shapes, three treatments

| Shape | Example | Behaviour |
|---|---|---|
| **Environment broken** | `Cannot find module 'vitest'` | STOP. Surface the tool's own error verbatim. Never improvise, never try an alternate command |
| **Safety halt** | `DROP COLUMN` in the plan | Stop *before* anything reaches disk, even in auto mode. Numbered menu |
| **Guard fired** | `git push origin main` | **The command did not run.** Not advice |

## 7. Auto mode

`--auto`, or `config.auto.bounded`. Default off (D16).

| Changes | Does not change |
|---|---|
| approval gates become recorded rulings | **safety halts always stop** |
| | `spike` is never eligible — its output *is* a question |
| | `full` is explicit opt-in only |

The final report **must** print what was decided on the user's behalf:

```
Auto-ruled 2 gates:
  design → approved   (no open questions after investigate)
  review → accepted   (2 findings, both Minor, fixed in round 1)
Halts: none
Your gate is now the PR.
```

Without that block auto mode is a black box, and a black box is not trusted twice. Auto mode
**relocates** the human gate to the PR; it does not delete it.

## 8. On disk

```
myapp/
├─ .kiln/
│  ├─ config.json        committed
│  ├─ rules/index.md     committed — the router; the rule files beside it
│  ├─ hooks/pre-push.mjs committed — the floor's runner, so a stranger can read
│  │                       what runs in their repository (D90.3)
│  ├─ work/<id>/         committed — brief · plan · review · state.json
│  └─ tmp/<id>/          gitignored — this run's scratch space, writable
│                         before any gate; deleted at the end of SHIP (D106)
└─ (your source)
```

| Question | Answer | Decision |
|---|---|---|
| Does kiln commit at each gate? | **No.** SHIP is the only commit | D36 |
| What does the SHIP commit stage? | an **explicit path list** — never `git add -A`, never a broad commit because the tree is dirty | D67c |
| Can `work/` be kept out of the PR? | `work.committed: false` | D36 |
| What does a mid-run crash lose? | nothing — artifacts and `state.json` are durable the moment they are written | D36 |

## 9. Coming back to unfinished work

| `status` | What `/kiln:kiln 42` does | Decision |
|---|---|---|
| `in_progress` | resumes at the stopped step — but **does not trust the checkboxes**; runs a cheap preflight first | D58, D67d |
| `reviewed` | goes straight to ship | D24 |
| `shipped` | opens pass N+1, after confirmation — **every gate must be given again**: approvals belong to the pass that earned them, so pass 2 starts with source edits locked exactly as pass 1 did | D24, D85 |
| `halted` | **re-presents the halt's numbered menu**, never continues past it | D58 |

A week-old resume anchors REVIEW on `last_verified`, not on `base` — a real run anchored wrongly
produced a review artifact of **100 MB and 1.7 million lines** (D67a, D76).

## 10. Several works, several sessions

| Situation | Behaviour | Decision |
|---|---|---|
| two works with **disjoint** claims | run concurrently | D66 |
| two works whose claims **overlap** | the **second plan gate halts**, naming the first work id — the refusal is at claim registration, not at write time, or both would block each other | D72 |
| the same work, a new session | the new session **adopts it out loud**; the displaced session's next guarded write blocks saying so | D66 |
| kiln is not driving this session | **allow everything** — kiln does not police sessions it is not running | D33 |

kiln **never requires a git worktree**: submodule layouts and fixed absolute build paths cannot
provide one (D66).

## 11. A different project shape

| Need | How | Decision |
|---|---|---|
| multi-repo / submodules | one config entry, not an architecture | D38 |
| an integration branch not called `main` | `vcs.integration_branch` — `v3-master` is as valid as `main` | D37 |
| **a different integration branch per module** | `integration_branch` accepts `{ "<module>": "<branch>" }` when `repo.kind` is `multi`; unlisted modules fall back to the scalar | D81 |
| a stack kiln does not ship | **write one JSON file** — `stack-node` is ≈ 20 lines and zero code | §3d |
| a convention this project has already decided | a rule file under `.kiln/rules/`, routed by a path glob in `index.md`. `kiln doctor` fails on a row it cannot resolve, so a rule is never quietly not applied | D101 |
| an extra check (Playwright, lint, typecheck) | one more entry in `steps[]`. There is **no second mechanism** for running checks | D73 |
| blocking a stack's dangerous operation | a **guard script**. Config never carries a safety regex | D30 |

## 12. DNA — v1.2

**v1 ships no DNA.** One reason: it adds `uv` + Python 3.11+, an install-time dependency on a
stranger's machine (D6, D2). v1 runs tier 0 — a **real grep implementation, never a no-op** (D47).

```
config.knowledge.tier    0 = grep (v1)   |   1–2 = DNA (v1.2)
```

### Commands (v1.2)

| Command | Does |
|---|---|
| `/kiln:kiln dna` | opens the explorer in a browser (loopback server, tab opens itself) |
| `/kiln:kiln dna init` | **full scan** — bootstraps the store |
| `/kiln:kiln dna update` | **diff scan** — *"Diff, don't re-scan"* |
| `/kiln:kiln dna --export` | writes **one self-contained HTML file** — opens from a double-click, survives an email |

| Behaviour | Detail | Decision |
|---|---|---|
| what `update` anchors on | **always `origin/<integration_branch>`, after a fetch** — whatever branch the user stands on. No `checkout main` needed, and no flag, because there is one correct answer | D79.1, D80, D82 |
| `update` on an empty store | **refuses and points at `init`**. Bootstrap is a full scan, update is a diff scan; a full scan of a large repo is not something a command called `update` starts by surprise | D79.2 |
| a scan on `feat/…` | may produce a preview; may **never** write `manifest.source_pins` | D80 |

### Automatic, with nothing typed

| When | Behaviour | Decision |
|---|---|---|
| **INVESTIGATE** | **fetch first**, then compare `manifest.source_pins` against `origin/<integration_branch>` — never against `HEAD` | D22, D82 |
| no drift | use DNA, full confidence | D22 |
| small drift | offer catch-up, **default yes** | D22 |
| large drift | use DNA, mark the drifted region **low-confidence**, **print the number**, offer catch-up, **default no** | D22 |
| **the fetch fails** (offline, no remote, auth) | the drift number is **not printed as zero** — the failure is named, the whole store is marked low-confidence, catch-up defaults to no | D82 |
| after SHIP | **nothing** — a PR may be rejected or rewritten; recording it as fact would put code into DNA that does not exist on the integration branch | D22 |

A month of drift can be **500 files**, and it must never silently become part of a ticket.

## 13. The pull request

| Carries | Does not carry |
|---|---|
| the impact report: `predicted 4 · actual 11 · ⚠ 8 beyond prediction` | **log content** |
| the run's `state.verify[]` rows — `{id, cmd, exit, range}` | |
| the user's approval **verbatim** | |

An empty or non-descendant diff at REVIEW **halts** — there is no clean review of nothing (D56).

**Guard rail:** never open a PR on a stranger's repository with agent-authored code. Fork → work
on the fork → PR into the fork's own default branch (§4).

## 14. When kiln itself breaks

| Symptom | What the user is told | Decision |
|---|---|---|
| `state.json` unreadable | **BLOCK**, naming the exact path and the fix | D33 |
| a stack guard crashes | **BLOCK**, printing the trace, the file, and `kiln doctor`; recovery must not require editing kiln's own code | D33, D43 |
| config missing or broken | `guard-protected-branch` falls back to a hardcoded `main`/`master` list and **still blocks** — never falls back to allow | D33 |
| older `schema_version` | migrated in memory, one line pointing at `kiln doctor --write`; a tracked file is never silently rewritten | D39 |
| newer `schema_version` | **refused**, printing both numbers rather than guessing | D39 |

Updating kiln: `/plugin update kiln`, **then `kiln doctor`**. The plugin update replaces
kiln and touches nothing in your project (D39), which is the point — and it means a checkout
that already had the push floor keeps the hook the *older* kiln wrote. Doctor calls that
`stale` and `kiln doctor --write` replaces it. `kiln open` says so too, once per run, because
the one instruction that used to sit here said *"that is all"* and it was not (D104).

## 15. What can be trusted, and what is only audited

| **Enforced — the command does not run** | **Audited, or a named ceiling** |
|---|---|
| pushing to a protected branch | **source** edits through an interpreter or heredoc (`python -c "open('src/a.ts','w')"`) — D64 covers redirection, `tee`, `sed -i`, `cp`/`mv`; the rest needs shell parsing D34 refuses. An inline program that *names* a file the enforcement is made of is blocked without being read (D98), so the ceiling is source only |
| `rm -rf` / `git clean -xfd` resolving outside the repo | whether a gate record reflects what the human said — the user reads their own verbatim words back |
| a failing test reported as passing (exit code only; **stdout is never parsed**) | the agent following a URL a ticket asked it to fetch — skill text, not enforcement (D59) |
| the agent editing `state.json` / `config.json` through `Edit`/`Write` | `node` absent from `PATH`, or a dispatcher failure → **fails open** (D54) |
| writes outside the sandbox (resolved path, segment compare; a symlink leaf is **rejected**, not followed) | a hook exceeding its `timeout` → **allows**. `timeout` bounds latency, never protection (§1.6 row 4) |
| a `plan.md` edited after its gate was approved | "kiln's own code performs no network egress" is a **static CI grep**, not a runtime test (D35) |
| opening a PR before the ship gate, or from `spike` | a PR opened through the forge's **web UI** or a **direct API call** (D77) |

Guards fire **and block** under `bypassPermissions`, and fire **and block** inside subagents —
both measured, not assumed (§1.6 rows 6 and 7).

## 16. Language, and what leaves the machine

| | | Decision |
|---|---|---|
| artifact language | `config.artifact_language`, declared **once** (default `en`), never inferred per run | D5 |
| chat language | follows the user | D5 |
| **never translated** | identifiers · DB table/column/value names · UI labels · error strings · lang keys · filenames | D5 |
| network, v1 | kiln's own code performs no egress **except `git fetch` / `git ls-remote` against the configured remote**, which the drift check needs — both allowlisted by name in the CI grep | D59, D82, D83 |
| network, v1.2 | the explorer opens a **listener bound to `127.0.0.1`** — a listener, not egress. The grep's allowlist **names the Python tree**; if that proves uncheckable, the Python tier is recorded as **ungraded**, never covered by implication | D83 |
| telemetry | none. The brand hotlink is removed from the vendored companion | D11 |

## 17. What kiln deliberately does not do

| Not | Because |
|---|---|
| replace superpowers / agent-skills | kiln adds nothing to their surface; it forks five of their skills under `kiln-*` names so an install needs no second plugin |
| ship clients for tracker / VCS / browser | MCP and the CLIs already exist |
| require a tracker | the primary entry point is **one sentence** |
| require DNA | the grep tier works immediately |
| require Docker / a DB / a browser | those are project facts, declared in `.kiln/` |
| improvise an alternate command when the user's fails | environment failures **stop**; they are not worked around |
| poll a tracker to keep DNA fresh | `tps-dna-watch` was retired by its own owner; kiln writes no poller (D13) |

## 18. What will annoy the user — stated in advance

| Thing | Weight |
|---|---|
| `guard-gate` has the widest surface of any guard, after D64 and D77 | it has now run: the live-harness evidence, six acceptance runs, and ten real checkouts. Two false blocks were found that way and fixed (D93, D103); assume the rate has not reached zero |
| a crashing stack guard blocks **every** edit until it is fixed | deliberate — a guard that fails open makes D7 a paper promise |
| `spike` cannot ship, and ratcheting up is another halt | one more step |
| `full` has four gates | the price of the heaviest path |
| five skills forked from superpowers | upstream's measured fixes do not arrive on their own; a human reads the releases at P5 |
| ~25 ms added per tool call | node cold start plus one to three `state.json` reads |
| the explorer is ≈ 198 KB of vendored front end | lives under `vendor/`, excluded from lint — kiln does not maintain it |
