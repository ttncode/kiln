# The bar check: a change may not lower the bar it is judged by

> **Status: design, revised once after an adversarial review.** Phase B, item 4 of the skill-parity plan (the bar guard, with
> constraint-driven-development). An adversarial review comes before any code.

## The problem

An agent under pressure to get green has cheap roads there: skip the failing test, delete an
assertion, add `eslint-disable` or `@ts-ignore`, leave a stub or an empty `catch`, or loosen the
checker's threshold. Every one of them makes `kiln verify` green and REVIEW's readers may or may
not see it in a large diff. kiln's copies tell the agent not to (verification-before-completion,
kiln-implement's handover), and nothing checks.

## What proven tools do

agent-skills' constraint-driven-development ships a reference **floor guard**
(`references/floor-guard.md`, `2686b62`) with a fixed contract:
- input: the diff from the merge base to the working tree, untracked files included;
- five moves detected: a weakened threshold, a test made easier (`.skip`, a deleted test file,
  an assertion removed from a test that stayed), a silenced checker (a new suppression
  comment), unfinished work (a stub, an empty `catch`), a new exception row;
- exit `0` clean, `1` violation (block), `2` could not run — "never let a `2` read as a `0`";
- tightening is silent, loosening is loud; it reports the rule and the location.

It says it is "deliberately regex-shallow: it catches the cheap-road-to-green moves agents
actually make". Its thresholds live in a `CONSTRAINTS.md` kiln does not have.

## The design

**Name.** `kiln bar`, not "floor": kiln's floor is the pre-push hook (D90).

**Input.** The work's own change as REVIEW's readers get it — per checkout, from the work's
base, untracked files included, `.kiln/` and the `dirty_at_open` paths left out (D189, D199) —
through a variant of `changePatch` that returns `{ patch, failures }`: today a failed
`git diff` or a submodule whose base cannot be read comes back as an empty string, which a bar
check would read as clean. A failure is a finding (`not run: <reason>`), never an empty list.
Known limit: a file already dirty at open is left out whole, so a suppression the work adds to
it is not seen.

**Detection.** An excerpt of the floor guard's patterns (MIT, recorded in `NOTICE` the way the
gitleaks rules in `lib/dna/secrets.mjs` are), rewritten into small functions to meet kiln's lint
limits, with the diff walked by its `diff --git` and `@@` headers rather than by `---`/`+++` at
line start (a removed SQL comment `-- x` reads as a header otherwise). Adapted where a measured
case demands it:
- **Test files** come from the stack (`bar.tests`, globs): `*Test.php`, `tests/**`,
  `__tests__/**`, `*.test.*`, `*.spec.*`, `test_*.py` with a path boundary — the floor guard's
  `test_` matched `latest_news.php`.
- **Skips** are looked for in test files only (`stream.skip(10)` is not a skipped test), with
  the stack's forms added: `markTestSkipped`, `markTestIncomplete`, `@group skip`, `#[Skip]`.
- **Removed assertions** use the stack's `bar.assertions` (`$this->assert*`, `self::assert*`,
  `expect(`, `assert`), in test files that still exist.
- **Suppressions** add `@phpstan-ignore*`, `phpcs:ignore`, `@codeCoverageIgnore`,
  `pylint: disable`.
- **Stubs**: `TODO` only inside a comment; `NotImplementedError`, a `Not implemented` throw; an
  empty `catch` across lines and with a typed parameter.
- **Checker configs** named by the stack (`bar.configs`): a changed config file is one
  `checker-config-changed` finding for the file, since a number's direction in an arbitrary
  config cannot be read and a version pin is not a threshold.
- **Not scanned**: paths `.gitattributes` marks `linguist-generated` or `linguist-vendored`,
  `*.min.*`, and lockfiles — each named in one line, not searched (an unminified vendored file
  gave 17 findings).

Each finding is keyed by a short hash of rule, file and line text, so fixing one does not
renumber the rest.

**Where it bites.** At the review gate, computed by `kiln gate <id> review` itself — not read
from a file the agent can edit, and not stale after REVIEW's fix pass. A finding the fix pass
removed simply no longer exists. The gate refuses unless `review.md` has a `bar:` paragraph that
accepts each remaining finding by its key with a reason (`bar: 3f2a accepted: <why>`), and the
gate shows the user those lines. It is computed again by `kiln ship`, which prints any finding
the tree gained after the review gate. `kiln practices --stage review` also writes the findings
beside the readers' inputs, so every reader sees them.

**Auto mode.** D16 relocates the human gate to the pull request; a lowered bar is not a gate
question but a safety halt, like BMAD's failed matrix test audit. So `--auto` is refused while
any finding is accepted in `review.md`, and the orchestrator halts and renders the review gate
for the user rather than retrying. This needs its own decision entry.

## Tests

Must-find and must-not-find tables for node and php-ci3 (each move; `stream.skip`, `const TODO`,
`latest_news.php`, a SQL `--` comment, a vendored file); the root and a submodule; a line
already present at open is not found; a failed diff is a `not run` finding; the gate refuses a
missing or partial `bar:` paragraph, forgets a finding the fix pass removed, and refuses
`--auto` over an accepted one; `kiln ship` names a finding added after the gate.

## The review, and what changed

Blocker: `changePatch` turns every git failure into an empty diff, which would read as clean →
a variant that returns failures. High: `bar.md` went stale after the fix pass and the agent could
edit it → the gate computes the findings itself, keyed by hash; PHP was mostly blind and the
test-file rule misfired → stack fields for tests, assertions, skips, suppressions; false
positives (`stream.skip`, `const TODO`, vendored files) → skips in test files only, TODO in
comments only, generated and vendored paths named not scanned; wrong citations (D54, D191) → D90
and D16, with the auto refusal argued as a halt. Medium: an excerpt, not a verbatim copy; one
finding per changed config file; the `dirty_at_open` limit named; header parsing; the check no
longer depends on the readers' inputs being written, and runs again at ship.
